# StakeMode source and runtime provenance

Application source base: [aliasmode/aliasmode](https://github.com/aliasmode/aliasmode) commit `3830cc4f8350b3b21e57dc962a182e7bdfdb3f05` (AliasMode beta.51, Apache-2.0). This is a clean upstream source base. No Stake1, DPN or AI integration from AliasMode Game is copied into StakeMode.

Downstream product: StakeMode `0.1.0-preview.2`, Windows x64, Tauri identifier `com.solomongs.stakemode`, binary `stakemode.exe`, managed sidecar `stakemode-sidecar.exe`. The source is published on the private repository's `stakemode` branch; existing `main` remains a separate AliasMode Game product.

The Chromium runtime uses the upstream-pinned CloakBrowser wrapper `0.4.11` and Chromium `146.0.7680.177.5`. Browser installation and desktop packaging retain the original SHA-256 verification rather than downloading an unverified executable.

The patched Firefox runtime is [aliasmode/aliasmode-firefox](https://github.com/aliasmode/aliasmode-firefox), source commit `013ebace6cc69c1979c7a86636139e91face6419`, workflow run `36421765188`, engine `152.0.4-beta.30`. CI checks the workflow identity, repository, branch, source commit and successful completion before accepting its single Windows x64 archive. It records the archive and executable hashes, checks the reported version, and verifies the copied packaged executable. The engine's original `aliasmode.exe` filename is preserved inside the private runtime bundle so the upstream engine identity and license remain accurate.

StakeMode applies the downstream `stakemode-firefox-extension-ui-v1` JavaScript compatibility patch after verifying that Firefox payload. The pinned engine skips its page actor on `moz-extension://` documents, which prevents add-on popup/options pages from reporting lifecycle events or accepting browser-view input. The patch removes only that early return in the two exact, hash-checked `JugglerFrameChild` module copies. The native executable and upstream source/archive pins remain unchanged. Changed runtime archives and modules receive separate before/after SHA-256 records in `BROWSER-PROVENANCE.json`; they are not represented as unmodified upstream archives. Exact original/modified module sources, the patch and MPL-2.0 notices ship under `firefox/stakemode-patches/firefox-extension-ui`. Packaging rejects unexpected module versions, duplicate targets and modified unrelated entries. Native acceptance checks the resulting archive hashes and actual popup/options behavior in both engines.

The Bun sidecar compiler is official Bun `1.2.21`, Windows x64 baseline archive SHA-256 `23f2df1f40d963e5b6104e1a565df992aab8968da5004f460617073843b8b8be`. Baseline compilation supports x64 CPUs without AVX2.

Official Node.js `22.23.2`, Python `3.13.7`, and the Python Playwright wheels use pinned download URLs and SHA-256 values in `scripts/prepare-windows-bundle.ts`. JavaScript dependencies are pinned by `bun.lock`, native dependencies by `src-tauri/Cargo.lock`.

Each release includes the final validated source SHA, browser provenance, workspace acceptance report and SHA-256 checksums. The Windows preview is unsigned and has no automatic updater. Source and bundled-engine licenses remain in the distribution. No live wagers are part of CI acceptance.

## Windows installer template

The NSIS build uses the Tauri CLI 2.11.4 template pinned to upstream commit `8909f221d1515955fc843808032bdc5d62209c96`. StakeMode moves its additional plugin directory registration before the installer hooks so the early process-presence guard can compile. The guard continues to refuse installation without terminating running applications. The exact original/modified hashes, template and Apache-2.0 OR MIT notices ship in `notices/tauri-nsis/` and are recorded in [`src-tauri/windows/tauri-nsis/provenance.json`](../src-tauri/windows/tauri-nsis/provenance.json).

That pinned bundler's [`patch_binary` and `bundle_project`](https://github.com/tauri-apps/tauri/blob/8909f221d1515955fc843808032bdc5d62209c96/crates/tauri-bundler/src/bundle.rs) replace `__TAURI_BUNDLE_TYPE_VAR_UNK` with the equal-length `__TAURI_BUNDLE_TYPE_VAR_NSS` before creating the NSIS payload, then restore the compiled main executable. Installed acceptance therefore derives the complete expected unsigned payload from the compiled image using only that single pinned replacement. It validates bounded Windows x64 PE headers, requires exactly one pristine marker, and compares every installed byte plus the full SHA-256. Missing, duplicate or prepatched markers and all other byte changes fail verification. The report records the source pin, marker offset, file lengths and compiled/expected/installed digests without paths. The sidecar retains its unchanged exact SHA-256 comparison. This verifier applies to the unsigned preview; signed payloads require their own exact packaging provenance.
